# Аналитика курса → Google Sheets

Курс копит события: ответы в тестах, шаги тренажёров, выдачу заказов кассиром, клапаны 3D, переходы и клики. Пачками отправляет их в веб-приложение Google Apps Script, а оно дописывает строки в таблицу.

- Сборщик: `course/js/gb-log.js`.
- Настройки: `course/js/gb-log-config.js`.
- Приёмник: `analytics/sheets.gs`.

## Установка — один раз, ~10 минут

1. Создай пустую Google-таблицу, например «Белые Грибы — аналитика».
2. **Расширения → Apps Script.** Удали содержимое `Code.gs` и вставь `analytics/sheets.gs` целиком.
3. В начале скрипта впиши токен: `const TOKEN = "…";` — любая длинная случайная строка. Сохрани.
4. Выбери функцию `setup` и нажми **Выполнить**. Google попросит доступ к таблице — разреши. Появятся листы `events` (с шапкой) и `summary` (сводки).
5. **Развернуть → Новое развёртывание → Тип: Веб-приложение:**
   - «Запуск от имени»: **Я**;
   - «У кого есть доступ»: **Все** (ученики в LMS не залогинены в Google, иначе запросы не пройдут).

   Нажми «Развернуть» и скопируй URL, который кончается на `/exec`.
6. Открой этот URL в браузере — должно появиться `ok`.
7. В `course/js/gb-log-config.js` впиши:

   ```js
   endpoint: "https://script.google.com/macros/s/…/exec",
   token: "тот же токен, что в TOKEN",
   ```

8. Пересобери SCORM-пакет и загрузи в LMS.

Если скрипт потом меняли, нужно **Развернуть → Управление развёртываниями → Изменить → Новая версия**. URL при этом останется прежним.

## Почему сборщик не тормозит LMS

- События копятся в памяти и уходят пачкой раз в 30 секунд. Первая пачка — через 8 секунд после старта.
- Отправка асинхронная: `fetch` с `no-cors` и `keepalive`, таймаут 15 секунд. Ответ никто не ждёт, интерфейс не блокируется.
- Тело запроса — `text/plain`: без предварительного CORS-запроса, один запрос на пачку.
- Нет сети — очередь лежит в `localStorage` и уходит, когда сеть вернётся или при следующем заходе. После ошибки пауза растёт до 5 минут, чтобы не долбить плохой канал.
- При сворачивании и закрытии вкладки остаток уходит через `sendBeacon`.
- Ограничения: очередь — до 1000 событий, сеанс — до 5000, ошибок скриптов — до 20 за сеанс. Пачка — до 60 событий и ~48 КБ.
- Любая ошибка внутри сборщика глушится. Пустой `endpoint` — сборщик полностью выключен.
- С SCORM сборщик не пересекается: `cmi.*` не пишет, только читает `student_id`.

## Что в таблице (лист `events`)

| Колонка | Что это |
|---|---|
| `received_at` | когда строка пришла в таблицу |
| `event_time` | когда событие случилось у ученика (часы его устройства) |
| `event_id`, `seq` | уникальный id события и его номер в сеансе |
| `session` | id сеанса — одно открытие курса |
| `learner` | ученик: `h:…` — хэш `student_id` из LMS (по умолчанию), пусто — вне LMS |
| `role` | выбранная должность / позиция |
| `course` | версия курса из конфига |
| `in_lms` | 1 — курс открыт в LMS |
| `page` | где был ученик: `cooking/pita`, `ingredients`, `app:Тренажёр «Повар»`… |
| `type` | тип события (ниже) |
| `name`, `value` | что и какой ответ/действие |
| `correct` | 1 — верно, 0 — ошибка, пусто — не оценивается |
| `ms` | длительность, мс |
| `data` | доп. поля в JSON |
| `user_agent` | браузер и устройство |

## Типы событий

| `type` | `name` | `value` | `correct` / `data` |
|---|---|---|---|
| `session_start` | — | — | `data`: размер экрана, сколько событий ждало с прошлого раза |
| `session_end` | — | — | `ms` — длительность сеанса |
| `nav` | id главы | — | — |
| `who` | `position` / `role` | `aup`, `crew` / `cook`, `cashier`, `universal` | — |
| `click` | текст кнопки или ссылки | — | `data`: data-атрибуты и id элемента |
| `quiz` | текст вопроса | выбранный ответ | верно ли |
| `pack_quiz` | `pack-q1…3` — ситуационный тест по упаковке | вариант | верно ли |
| `flap` | `модель:клапан`, например `pita:sezonnyi` | `press` / `release` | в режиме задания — попал ли в нужный клапан |
| `video_open` / `video_close` | id видео | — | у `video_close` `ms` — сколько смотрел |
| `trainer_start` | `cook` / `cashier` | — | — |
| `trainer_result` | `cook` / `cashier` | `баллы/максимум` | сдал ли |
| `cook_step` | `блюдо#номер шага`, например `angus#3` | тип шага | верно ли; `ms` — время на шаге; `data.err` — текст ошибки |
| `cook_dish` | блюдо | — | без ошибок и в срок; `ms`; `data`: errors, late, limit |
| `cashier_open` | заказ | какую упаковку открыл | `data`: номер на бине, обучение ли |
| `cashier_give` | заказ | какую упаковку отдал | верно ли; `data`: открывал ли, обучение ли |
| `cashier_run` | — | `баллы/максимум` | сдал ли; `ms`; `data.skipped` |
| `js_error` | текст ошибки | файл:строка | — |

Лист `summary` — готовые сводки:
- события по типам;
- доля верных ответов по вопросам;
- шаги повара с ошибками;
- блюда;
- заказы кассира;
- итоги тренажёров;
- ошибки скриптов.

Пересобрать сводки — функция `buildSummary`.

## Ограничения Google

- Apps Script держит примерно 30 запросов одновременно. Пачка раз в 30 секунд — это около 2 запросов в минуту на ученика: сотни учеников одновременно выдержит. Если курс запустят на тысячи человек в один час, нужен настоящий сервер-приёмник. Формат пачки менять не придётся — только `endpoint`.
- В таблице не больше 10 млн ячеек. Когда лист `events` дорастает до 400 тыс. строк, запись переходит на `events_2`, `events_3`… Сводки в `summary` смотрят только на `events` — для новых листов поменяй диапазон в формулах.
- Повторы отсекаются по `event_id` в течение 6 часов. Если пачка ушла дважды с большим разрывом (ученик вернулся на следующий день), возможен дубль. Такие строки видны по одинаковому `event_id`.

## Личные данные

По умолчанию `learner` — хэш `student_id`. Одного ученика видно во всех его сеансах, но имени и логина в таблице нет. Писать `student_id` как есть — `learner: "raw"` в конфиге. Не писать совсем — `learner: "none"`.
